# Save 阶段：确认与保存

方案生成的最后一层，三步：**向人索取名字**、**写盘前自检**、**落盘到待推送区**。

这一层看着最像收尾流程，实际上藏着这条流程里唯一一个「不允许自动通过」的门。整条 plan 流程没有任何 guard——它不提交、不推送、不改任何外部系统，所以没有需要拦的动作。它唯一需要人的地方就在这里：**给这份方案取个名字**。而这件事之所以不能由 agent 代劳，理由不在命名本身。

---

## Step: S01 🚦 slug 索取门（禁止 default）

> - **输入**：`W02` 写好的方案正文。
> - **输出**：三个候选名字，以及人从中选定的那一个。
> - **失败时**：**禁止跳过本步直接 default 到一个名字**。候选少于三个等于没给选择。
> - **完成标准**：确认门已记录，且至少三个候选被摆出来过。

这是本流程唯一的门。做法是：**先输出三个候选**，说明各自的命名角度（按组件 / 按范围 / 按动作），然后结束这一轮，等人真的回话。人可以选一个，也可以自己给一个新的。

**这个门与「预授权」恰好相反，而这个对比是理解它的关键。** 流程里另一类门是可预授权的：默认停下问人，但如果配置里显式开了对应的开关，就可以自动记一个通过决定往下走。那类门保护的是**可逆、且决策只依赖已知信息**的动作——比如提交前的确认，diff 已经摊在那里，人看不看结果都一样。

这个门不是那样。它要的不是「批准一个已知选项」，而是**一个只有人能给的输入**。三个候选都是我编的；哪个更贴近人心里那个项目、哪个在半年后还能被认出来、哪个和团队既有的命名习惯一致——这些信息不在我这边。所以这里没有可预授权的版本：**能被预授权的前提是决策内容已经确定，而这里恰恰是内容缺失。**

**判据为什么同时要求「门已记录」和「≥3 个候选」**：只要求门会漏掉一种很自然的做错方式——摆一个候选，问「就叫这个行吗」，人说行，门记录成功。形式上完整，实际上**没给选择**。一个候选加一句「行吗」是在请求追认，不是在请求选择;人在这种问法下的默认反应是同意,而那个同意携带的信息量接近零。三个候选强制我真的从不同角度想过命名,也让人的选择变成一次真实的比较。

**另一种做错方式：把候选凑够三个。** 生成三个只有措辞差别的名字(`fix-alert-preset` / `alert-preset-fix` / `preset-alert-fix`)在计数上满足判据,在实质上和一个候选没区别。三个候选应该代表三种**命名角度**,让人能看出「这份方案可以被理解成什么」——而那个选择本身往往会反过来暴露方案的重点被理解错了,这是这个门附带的、也是最有价值的产出。

## Step: S02 写盘前自检（slug lint / schema lint）

> - **输入**：`S01` 选定的名字、`W02` 的正文与各层收集的字段。
> - **输出**：名字命名规则与文档结构字段的逐项自检结果。
> - **失败时**：任一项不过就**不写盘**——不要先落盘再回头修。
> - **完成标准**：每一项自检结果都是 `pass`。

这一步是纯机械的:名字符不符合命名规则(字符集、长度、有没有和已有方案撞名),各个字段符不符合结构约定(必填的在不在、枚举值取自封闭集合没有自造)。逐项落一条结果,判据要求**每一条都是 pass**,而不是「最后一条是 pass」。

**用「每一条」而不是「最新一条」是有原因的。** 如果只看最新一条,那么先记若干条失败、最后补一条通过,判据就满足了——而账本上留着的是一串没人处理的失败,读起来却是「自检通过」。全称检查让这条路走不通:任何一条不是 pass,这一步就关不掉。

**最典型的做错方式:先写盘,再修 lint。** 这个顺序看起来只是省事,代价在于**方案文档一旦落进待推送区,它就已经可以被下游取用了**——下一个环节读到的是一份没通过自检的文档。而「已落盘」这件事本身会降低回头修的动力:反正已经在那儿了。判据把顺序钉在写盘之前,是因为这是唯一一个修正代价还很低的时刻。

## Step: S03 写入 pending 区

> - **输入**：通过自检的名字与正文。
> - **输出**：方案文档落盘到待推送区。
> - **失败时**：写盘失败要如实报,不要以为「内容已经生成」就等于完成。
> - **完成标准**：文档路径已记录,且状态为 `pending`。

最后一步:把方案写进待推送区,状态标为 `pending`(等待推送)。判据要两件事——**路径**和**状态**。

**路径要记,是因为下游需要它。** 后续的推送环节要按路径取这份文档;状态迁移也要按路径找到它。一个没被记下路径的文档在流程里等于不存在——内容确实生成了,但没有任何一步能确定地找到它。

**状态只允许 `pending` 这一个值**,因为这是这份方案在本流程里唯一合法的终态。它不该在这里就变成「已推送」或「已完成」——那些是后续环节的事,提前标上会让下游以为工作已经做过了。这是「把未完成标成完成」的一个具体实例:状态字段是给别人看的,而它一旦说错,别人不会去核对。
