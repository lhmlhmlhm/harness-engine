# 「终态」不等于「看起来没问题」

## 判据

一个外部检查到达终态，意味着**它自己说它结束了**。不是：

- 「已经跑了很久，应该好了」
- 「我修完了，所以应该会过」
- 「其它几项都过了，这项大概也会过」

## 为什么这条特别容易破

因为**未跑完和通过在那一刻长得一样**——都是「没有报错」。而人在等待时的默认倾向是
把沉默读成好消息。

真实案例：一次修完 analyzer 的意见就宣布 all-pass，而实际上还有两项在跑。
后来加的守卫是拿「已验证的版本号 == 最新推送的版本号」做硬校验，
因为「我觉得过了」不可校验，而版本号可以。

## 落地办法

把终态判断变成**可校验的谓词**，而不是判断：

- 有明确的状态字段 → 读那个字段，只接受枚举里的终态值
- 只有「还在跑 / 结束了」两态 → 等到「结束了」
- 完全没有信号 → **这本身是要上报的情况**，不是可以乐观跳过的情况

在这个能力里，`E01` 的 completion predicate 要求一条 `checks_terminal` 证据。
证据的值应该是**你读到的那个终态字符串**，不是你的结论。
