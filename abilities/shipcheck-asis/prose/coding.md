# 编码：按清单落地，不多不少

这个阶段把上一步和人对齐过的改动清单变成真实的代码改动。它的全部纪律压在两条判断上：
**改动不能超出清单**，**清单里的每个锚点必须实测命中**。做完的标准不是「代码看起来对了」，
而是「实际 diff 与清单一一对应、且能编译过」。这一层写文件只用文件写入工具，不用 shell heredoc。

## Step: K01 从计划提取改动清单

> - **输入**：已确认的计划文档里的改动清单
> - **输出**：一份可执行的工作清单（每项：文件路径 / 操作 / 锚点）
> - **失败时**：清单里的锚点在文件里定位不到 → 停下上报，不要就近找个相似位置顶替
> - **完成标准**：每一项都有明确的路径、操作和一个已验证存在的锚点

把计划里的改动清单读出来，逐项拆成「在哪个文件、做什么操作、以什么为锚点」。

**锚点必须实测命中，这是这一步的核心。** 清单写「在 `foo` 函数后插入」，就**先去 grep 出
`foo` 的实际位置**再动手。定位不到，就是现实与预期对不上——这属于必须停下来上报的情况，
不是自己找个「看起来差不多」的地方糊上去。就近顶替是这一层最隐蔽的失败：改动照样落了、
编译也可能过，但落错了地方，而且没人会知道，因为表面上什么都没报错。

## Step: K02 应用改动

> - **输入**：K01 的工作清单
> - **输出**：符合清单的改动 + 一条 diff 证据
> - **失败时**：单条改动反复卡住（约 3 次）→ 升级问人（修 / 改计划 / 跳过），不要闷头试第四次
> - **完成标准**：清单各项都已落地、无编译错误

按工作清单逐项落地。

**改动范围不超出清单，这是另一条核心。** 顺手清理无关代码、顺带改个不在清单里的地方——
哪怕改得对，也不要。原因不是洁癖：后面有一步专门拿实际 diff 和清单做对比来复核影响面，
一旦你改了清单外的东西，那次复核就失去了意义（它复核的是清单，不是你实际动过什么）。
确实需要偏离清单时，**先说明再改**——清单是上一步和人对齐的结果，静默偏离等于把对齐作废。

**每次编辑后顺手扫一眼编辑点附近有没有需要同步的东西。** 改了一个枚举值、一个计数、一个
版本号、一个「保留区间 N-M」之类的声明，往往在紧邻几行或别处还有一个跟它配套的地方需要
一起改。当场能修的就修；跨文件的就标记出来，让后面的一致性检查接手。

**不要用 heredoc（`cat << EOF > file` 这类）写文件，用文件写入工具。** 这不是风格偏好，
理由见 topic `heredoc-hangs`。shell 只用来读（查看、grep）和跑构建/测试命令，不用来写文件。

**单条改动卡住时，别闷头试第四次。** 同一处改了失败、再改再失败，通常说明你对现状的理解
和真实情况不符——这时候第三次以后再试，只是在同一个错误认知上反复撞墙。约三次拿不下就
升级问人（继续修 / 改计划 / 跳过这条），把选择权交回去，而不是自己越试越远。

## Step: K03 编译检查

> - **输入**：改完的工作区
> - **输出**：编译结果（过 / 未过）
> - **失败时**：编译报错 → 回 K02 定点修（约 3 次内），修不动就升级问人
> - **完成标准**：纯编译通过；没有编译工具链的项目（如纯文档改动）可跳过

用项目的构建命令做一次**只编译、不跑测试**的检查——目的是尽早抓出语法/类型层面的错，
把「代码写坏了」和「逻辑不对」这两件事分开。跑测试框架是下一层的事，这里明确不做。
跑命令前先看一眼项目有没有记录过的平台怪癖，有就按怪癖来。

## Step: K04 改动范围复核

> - **输入**：改完的工作区 + 计划的改动清单
> - **输出**：范围比对结果（完全一致 / 漏改 / 越界 / 完全不符）
> - **失败时**：完全不符 → 回 K02；漏改或改到清单外 → 停下问人确认
> - **完成标准**：实际改动文件集与清单一致，或差异已被人确认接受

把实际改动的文件集合和计划清单做集合比对：

- **完全一致** → 通过。
- **漏改**（实际是清单的合理子集）→ 停下问人：是有意少改，还是漏了。
- **越界**（改了清单外的文件）→ 停下问人：这正是 K02 要防的情况在这里兜底。
- **完全不符** → 退回 K02 重来。

这一步是「改动不超出清单」的最后一道结构性检查。不要因为「我知道自己为什么多改了那个文件」
就自己放行——你清楚理由，但和你对齐过清单的人不清楚，得让他确认。这道复核是引擎按前几步的
证据核对的，不是靠你在这里自述「我没越界」——自述在这里不算数。

## Step: K05 本层收尾打分

> - **输出**：本层的完成打分与交接标记
> - **完成标准**：K01–K04 均已通过

发出本层收尾打分，交接给验证阶段。
