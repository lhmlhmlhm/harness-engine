# 分级是给作者的决策信息，不是你的情绪刻度

## 现象

每条发现要打一个级别：阻断 / 建议 / 吹毛求疵。很自然会把它当成「我有多在意这条」的
表达——我越不爽就标得越重。这是把分级用反了。

分级的读者是**作者**，不是你。他看到级别，据此决定「这条我现在必须改，那条我可以先放着」。
所以级别是一条给对方用的**决策信息**，你的情绪不在其中。

## 为什么这条代价不对称

标错的两个方向后果完全不同：

- **建议标成阻断** → 作者被迫改一件本可以商量的事。你花掉了他的时间，也花掉了你「阻断」
  这个词的可信度——下次真的阻断，他也当成你又在较劲。
- **阻断标成建议** → 作者合理地把它放进「以后再说」，于是一个真的会出事的问题被放过了。

一个是**逼人改不该改的**，一个是**放过该拦的**。两者不能互相抵消，也不该用「差不多重」
来回避——它们错在相反的方向上。

## 正确做法

给每条发现定级时，只问一个问题：**这个问题不修，能不能合入？**

- 不能 → 阻断。要能说清「会坏在哪」，不是「我不喜欢」。
- 能，但明显更好 → 建议。
- 纯口味、不影响正确性也不违背该库既有约定 → 吹毛求疵，甚至干脆不提。

零发现时明确说零发现。凑一条「建议」出来只会稀释你其它发现的分量。
