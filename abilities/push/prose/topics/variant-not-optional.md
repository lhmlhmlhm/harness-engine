# 「变体专属」不能建模成「可选」

## 现象

一条流程有两个形态，某些步骤只属于其中一个形态。看起来最省事的做法是把它们都标成
`optional`：走另一个形态时反正不跑，不就行了？

不行。这两个词说的是**不同的事**：

- `optional` 说的是「这一步**可以不跑**」——它存在，只是这次没做，会留下一条「跳过」的决定。
- `variants` 说的是「这一步在这个形态里**根本不存在**」——没有可跳过的东西，也没有决定可记。

## 用 optional 建模会坏在哪

把变体专属步标成 optional，等于告诉引擎「两个形态的步骤都属于每一次 run，只是有些没做」。
于是一次**走错了变体**的 run，可以合法地把**对方形态**的步骤一个个跑完、并且**干净地关闭**——
因为对引擎来说那些步骤本就属于它，跑完就是完成。

最恶劣的是**事后无法分辨**：这条跑错变体的 run，日志和一条正确的 run 长得一模一样，
全绿、全关闭、没有任何一条「跳过」记录能提示「你其实不该碰这些步」。错误从头到尾静默。

## 正确做法

变体在 `open` 时解析并**钉死**，此后流程形态不可变。属于本次变体的步才存在；
非本变体的步 `enter` 和 `skip` **都拒绝**——因为「不适用」不是「不需要」，没有决定可以记录。

这样一次走错变体的 run 会在**碰到对方步骤的第一下**就被拒，而不是安静地跑完再假装成功。
`optional` 留给「这个形态里确实存在、但这次可以不做」的步（如本流程的 `Z01sc`/`Z02`）。
