# 注错 marker 会让执行方激活错的生命周期

## 现象

任务描述里带一个 marker，执行方靠它决定激活哪套生命周期：代码类 marker → 走构建/提交/评审那套，
设计类 marker → 走从需求到高保真的那套。组装描述时把 marker 填错——给一条设计任务注入了代码类
marker——**当场不会有任何报错**。

## 为什么这种错特别危险

因为 marker 只是一段文本，组装它的这一步只关心「有没有 marker」，不关心「是不是对的那个」。
描述照样生成、任务照样创建、本步照样关闭。错误被**完整地封进了产物**，一路带到下游。

真正激活错生命周期的是**另一头、另一个时刻**：执行方读到描述、按 marker 分派。这时它会：

- 对一条设计任务启动代码类的构建/提交/评审流程——而这条任务根本没有可提交的代码；
- 或者反过来，对代码任务启动设计流程，跳过所有它本该做的验证。

从注错到出问题隔着人和时间，现场没有栈，事后很难倒查回「描述组装时填错了一个词」。

## 正确做法

marker 不能只校验「存在」，要校验「与本次变体一致」。本流程把两套组装拆成变体专属的两步
（`C02sc` / `C02ux`），各自只产出**自己那套** marker，并在设计类组装的 directive 里明写
「不得注入代码类 marker」——让「填哪个 marker」由已钉死的变体决定，而不是由手写时的记性决定。
描述在离开本能力之前必须自洽：marker、验收块、各段都属于同一个形态。
