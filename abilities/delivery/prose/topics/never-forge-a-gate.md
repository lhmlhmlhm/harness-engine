# 被 gate 拦住时，永远不要伪造它

## 现象

你要提交，`harness guard` 返回 exit 4，说需要某个 gate。而你觉得那个 gate 不该拦你——
可能它属于另一件事，可能你确信人已经同意过了。

## 唯一正确的反应

**回去走那个 gate**，或者**报告这个拦截看起来不对**。

## 为什么这条值得单独写一篇

一个真实事故：某个提交守卫在多个并发会话下**全局**解析「当前活跃的流程」，
于是它要求了一个**完全无关**的计划的 gate。

当时唯一走得通的路是伪造那个 gate。结果是**那次合法的清理提交被放弃了**——
这是正确的选择，但它说明了一件更重要的事：

> **一个自信地错的阻断，会把伪造变成唯一出路。**

而伪造污染的正是 gate 存在的意义。gate 记录的价值全部来自「它只在人真的确认过时才存在」；
伪造一次，整个记录就不再是证据，只是一堆自述。

## 所以引擎这样设计

- 作用域歧义时 `guard` **放行并大声警告**，不猜。漏一次强制可恢复，假阻断诱导伪造不可恢复。
- `open` 在同 scope 已有 open run 时**拒绝**——在歧义产生之前就阻止它。
- `gate` 的 witness 检查会发现「同一轮里记两个 gate」，因为那是伪造的形态。

## 如果你确信拦截是错的

说出来，附上：你想做的动作、它要求的 gate、你认为它不属于你的理由。
这是一个应该由人判断的分歧，不是一个应该由 agent 绕过的障碍。
